DOCLING RT-DETRv2 + best match + Union-Find

Analogia: concurso publico. clusters sao vagas (com tipo TITLE/TEXT/etc), cells sao candidatos (com texto). Cada candidato calcula NOTA com TODAS as vagas, melhor nota leva. Nota minima de corte: 20%.

1RT-DETRv2 cria os clusters (vagas)

Cluster 1: tipo=TITLE,    bbox=(50, 30, 500, 90)
Cluster 2: tipo=LIST,     bbox=(50, 100, 500, 350)
Cluster 3: tipo=PICTURE,  bbox=(550, 100, 900, 400)
Cluster 4: tipo=TEXT,     bbox=(50, 400, 900, 700)

2docling-parse extrai os cells (candidatos)

Cell A: bbox=(60, 40, 480, 80),    text="Aula 04 - Redes"
Cell B: bbox=(70, 110, 400, 140),  text="- Hardware"
Cell C: bbox=(70, 150, 400, 180),  text="- Software"
Cell D: bbox=(60, 410, 880, 690),  text="Sistema de telecomunicacoes..."
Cell E: bbox=(560, 800, 700, 820), text="Pg 1/12"   # rodape

3Cada cell calcula IoS com TODOS os clusters

Cell A "Aula 04 - Redes":
  vs Cluster 1 TITLE:    IoS = 0.95   # muito dentro
  vs Cluster 2 LIST:     IoS = 0.0
  vs Cluster 3 PICTURE:  IoS = 0.0
  vs Cluster 4 TEXT:     IoS = 0.0

  -> MELHOR = TITLE (0.95)
  -> 0.95 >= 0.20 threshold = CASA
  -> Cell A vai pro Cluster 1 (TITLE)

Cell E "Pg 1/12":
  vs todos clusters: IoS = 0.0
  -> ORPHAN

4Cluster pode ter MULTIPLOS cells

Cluster 2 LIST agora tem: - Cell B "- Hardware" - Cell C "- Software" texto final: "- Hardware\n- Software"

Sem "consumo" — cells sao distribuidos pra clusters em paralelo, varios podem cair no mesmo.

5Limpa clusters duplicados (Union-Find)

Cluster X: tipo=LIST_ITEM, bbox=(50, 100, 500, 130)
Cluster Y: tipo=TEXT,      bbox=(48, 98, 502, 132)   # quase igual

IoU(X, Y) = 0.95  -> > 0.8 threshold
-> mesma coisa pelo modelo
-> mantém o mais ESPECIFICO (LIST_ITEM > TEXT)
-> descarta Y

6Trata orphans e clusters vazios

if create_orphan_clusters=True:
    cells orfaos viram cluster TEXT novo  # preserva
else:
    descarta

if keep_empty_clusters=False:
    clusters vazios sao removidos
else ou se for FORMULA:
    mantem
Resumo Docling:
  • Pra cada cell, calcula IoS com TODOS clusters [O(M x N)]
  • Cell vai pro cluster com maior IoS (se >= 0.2)
  • Limpa clusters duplicados com Union-Find
  • Cells orphan viram cluster TEXT
  • Clusters vazios sao removidos (excetto FORMULA)

MINERU DocLayout-YOLO + greedy first-claim

Analogia: fila do banco. blocos sao caixas do banco (com tipo), spans sao clientes na fila. Caixas atendem clientes UM POR UM. Quando cliente eh atendido, sai da fila e nao pode ir pra outra caixa. Threshold de atendimento: 50%.

1DocLayout-YOLO cria os blocos (caixas)

Bloco 1: tipo=title,  bbox=(50, 30, 500, 90)
Bloco 2: tipo=text,   bbox=(50, 100, 500, 350)
Bloco 3: tipo=image,  bbox=(550, 100, 900, 400)
Bloco 4: tipo=text,   bbox=(50, 400, 900, 700)

2PyMuPDF extrai os spans (clientes)

Span 1: bbox=(60, 40, 480, 80),    text="Aula 04 - Redes"
Span 2: bbox=(70, 110, 400, 140),  text="Hardware"
Span 3: bbox=(70, 150, 400, 180),  text="Software"
Span 4: bbox=(60, 410, 880, 690),  text="Sistema..."
Span 5: bbox=(560, 800, 700, 820), text="Pg 1/12"

3Pool de spans disponiveis (estado inicial)

self.used_span_indices = set()   # vazio
spans_disponiveis = [Span 1, Span 2, Span 3, Span 4, Span 5]

4Processa cada bloco EM ORDEM (consome spans)

Processa BLOCO 1 (title):
  Span 1: IoS = 0.95 > 0.5 -> CASA
    used_span_indices = {1}
  Span 2-5: IoS = 0.0 -> nao casa

  # Bloco 1 fica com: [Span 1]

Processa BLOCO 2 (text):
  Spans disponiveis: [2, 3, 4, 5]   # Span 1 ja foi usado

  Span 2: IoS = 1.00 -> CASA, used = {1, 2}
  Span 3: IoS = 1.00 -> CASA, used = {1, 2, 3}
  Span 4-5: nao casa

  # Bloco 2 fica com: [Span 2, Span 3]

Processa BLOCO 3 (image):
  -> PULA matching de spans (regra especial pra image/table)
  -> Sintetiza bloco direto da bbox YOLO
  # Bloco 3 fica vazio (mas figura cropada)

Processa BLOCO 4 (text):
  Span 4: IoS = 1.00 -> CASA, used = {1, 2, 3, 4}
  Span 5: IoS = 0.0 -> nao casa

5Spans restantes sao DROPADOS (limbo)

self.page_text_inline_formula_spans = remaining_spans()
# = [Span 5]   --> orphan, NAO vai pro output principal

Spans nao consumidos ficam em "limbo" pra fixup de formula inline. Na pratica sao perdidos do output principal.

6Otimizacao: grid espacial 1D no eixo Y

Grid Y (faixas de 100px):
  Y=0-100:    [Span 1]
  Y=100-200:  [Span 2, Span 3]
  Y=400-500:  [Span 4]
  Y=800-900:  [Span 5]

Bloco 2 (text) tem y=100-350:
  So checa spans nas faixas Y=100-200, 200-300, 300-400
  -> ignora Span 1, 4, 5 (fora do range Y)
Resumo MinerU:
  • Cria pool de spans disponiveis
  • Pra cada bloco EM ORDEM (sequencial):
    • Filtra candidatos pelo grid Y (otimizacao)
    • Pra cada candidato: se IoS > 0.5, casa (e remove do pool)
  • Tipos image/table/chart: pula matching, sintetiza direto
  • Spans nao consumidos: vao pra limbo (efetivamente perdidos)

NOSSO DocLayout-YOLO + best match + threshold 0%

Analogia: vestibular sem nota de corte. regioes YOLO sao vagas (com tipo title/paragraph/etc), blocos vetoriais sao candidatos (com texto). Cada candidato calcula nota com TODAS as vagas, melhor nota leva. SEM nota de corte — qualquer um que tocou na vaga entra.

1DocLayout-YOLO cria as regioes (vagas)

Regiao 1: tipo=title,        bbox=(50, 30, 500, 90)
Regiao 2: tipo=plain_text,   bbox=(50, 100, 500, 350)
Regiao 3: tipo=figure,       bbox=(550, 100, 900, 400)
Regiao 4: tipo=plain_text,   bbox=(50, 400, 900, 700)

2PyMuPDF extrai os blocos vetoriais (candidatos)

Bloco A: bbox=(60, 40, 480, 80),    text="Aula 04 - Redes",    font=24pt
Bloco B: bbox=(70, 110, 400, 140),  text="- Hardware",         font=14pt
Bloco C: bbox=(70, 150, 400, 180),  text="- Software",         font=14pt
Bloco D: bbox=(60, 410, 880, 690),  text="Sistema...",         font=12pt
Bloco E: bbox=(560, 800, 700, 820), text="Pg 1/12",            font=8pt

Bonus que outros nao tem: font_size de cada bloco (do modo "dict" do PyMuPDF).

3Cada bloco calcula IoS com TODAS as regioes

# codigo real em hibrido_layout_aware.py
for b in blocos_vetorial:
    melhor_regiao = None
    melhor_overlap = 0.0
    for r in regioes:
        overlap = _intersecao_relativa(b.bbox, r.bbox)
        if overlap > melhor_overlap:
            melhor_overlap = overlap
            melhor_regiao = r

    if melhor_regiao and melhor_overlap > 0:   # THRESHOLD = 0%
        bloco.tipo = melhor_regiao.classe
    else:
        bloco.tipo = "paragraph"

Caso real - como cada um trata um span de raspao

Cenario: bloco vetorial "- Diagrama de Venn" tocou de raspao (IoS 10%) a regiao "title" do YOLO porque a bbox da regiao foi desenhada um pouco grande.

DOCLING

0.10 < 0.20 threshold

-> nao casa
-> cell vira ORPHAN
-> orphan vira cluster TEXT novo
-> preserva o texto sem
   classificacao errada

Resultado: TEXT (neutro, seguro)

MINERU

0.10 < 0.50 threshold

-> nao casa com title
-> bloco proximo (list)
   esta no bbox certo,
   mas o YOLO marcou title
-> span vai pra LIMBO
-> DROPADO do output

Resultado: PERDIDO

NOSSO

0.10 > 0% threshold

-> CASA com title
-> bloco vira "title"
-> markdown sai como
   "# - Diagrama de Venn"
-> CLASSIFICACAO ERRADA
   (deveria ser list_item)

Resultado: ERRADO

Solucao proposta: adicionar threshold 0.2 no nosso pipeline (igual Docling). Texto preservado como "paragraph", regex de bullet detecta "list_item" automaticamente. Resolve o caso Aula 03 Probabilidade que regrediu no Sprint 6.

Conclusao

Nosso pipeline tem a mesma filosofia do Docling: best match preservando orphans. A diferenca principal eh que nao temos threshold, o que causa classificacoes erradas em casos de raspao (Aula 03 Probabilidade no Sprint 6).

Proximos passos sugeridos:

  1. Adicionar threshold IoS 0.2 (igual Docling) — resolve Aula 03
  2. Trocar reading order pra usar block_no do PyMuPDF (igual Docling) — resolve Realismo multi-coluna
  3. Adicionar regra containment 80% pra figure/table — reduz falsos positivos
